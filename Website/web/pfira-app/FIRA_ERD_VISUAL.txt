                              LEGEND

Relationship Notation:
  │     One (required)
  │◄──── One (optional)
  ├─►    Many (one or more)
  │<     Many (one or more)
  └──┐   One-to-Many
  ┌──┘   Many-to-One

Entity Types:
  (PK) = Primary Key
  (FK) = Foreign Key
  (UNIQUE) = Unique Constraint
  (ENUM) = Enumerated Type
  (TEXT) = Text/VARCHAR
  (UUID) = Universally Unique Identifier
  (BOOLEAN) = True/False
  (TIMESTAMP) = Date/Time with Timezone
  (JSONB) = JSON Binary Format

                        RELATIONSHIP SUMMARY

1. auth.users → station_users (One-to-One via user_id)
2. auth.users → responder_users (One-to-One via user_id)
3. station_users → responder_users (One-to-Many via station_id)
4. station_users → responder_notifications (One-to-Many)
5. report_assignments → station_users (Many-to-One via assignee_id)
6. report_assignments → responder_users (Many-to-One via assignee_id)
7. messages → All user tables (Polymorphic Many-to-Many)
8. notifications → All user tables (Polymorphic One-to-Many)
